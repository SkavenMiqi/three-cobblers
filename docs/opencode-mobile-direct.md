# 手机直连 OpenCode V2：首版方案

## 目标

手机 TalkApp 成为 OpenCode V2 的网络客户端。电脑只运行 OpenCode 后台服务，不要求打开桌面 TalkApp 或 OpenCode 界面，不使用 ADB。手机的普通聊天仍直连模型；现有 PC 委派模式作为回退，不做双投递。

本机已验证 OpenCode v2.4.1 正常运行，`/api/info` 通过官方 CLI 访问成功；当前地址为 `127.0.0.1:28894`，手机尚未接入。未修改服务、Windows 防火墙或路由器配置。

## 扫码聊天预览

当前实现已改成**主聊天协作**：手机顶部「Harness」只管理配对。配对后自动发送版本化清单；后台验证 OpenCode API 并保存此配对的协作配置，不调用模型、不变更工具权限。普通聊天模型按需使用 `delegate_to_harness` 和 `check_harness_task`；后台按手机和 TalkApp 会话复用独立的 OpenCode 会话，使用电脑端默认模型。当前对话最近的文字会被动同步（最多 20 条、总计 5600 UTF-8 字节，不包含图片、附件或其他对话）；只有派单时才把文字背景作为资料交给 OpenCode。需要更新电脑后台和手机 App。电脑端启动参数决定工作目录，不会使用手机传入的任意路径。

电脑在项目环境运行 `python tools/talkapp_harness.py <工作目录>`，窗口会显示专用二维码。手机在同一局域网打开 `⋮ → 直连 Harness → 扫码连接`，首次扫码后不必输入地址和密码；电脑需保留此后台，也需允许手机连接此局域网端口。此入口复用固定 OpenCode 会话和原有权限策略，每两秒刷新可见文字；不是事件流。后台地址变化需重新扫码；可重启后台并加 `--forget` 解除配对。未确认送达的消息不自动重发。

## 旧版只读预览入口（已由扫码入口替换）

安卓版 `⋮ → 直连 OpenCode` 可填写私网 HTTPS 根地址（如 Tailscale Serve 提供的地址）和 OpenCode 服务密码，点击「连接并查看会话」。首版使用 OpenCode 官方 HTTP Basic 认证，只记住验证过的地址，密码不落盘。可读取近期会话和文字消息；不发任务、不审批、不把远端会话导入本地。下列配对链接和会话续跑是后续阶段，不是此入口的功能。

## 连接与配对

- **目标体验不是连接表单。** 进入「直连 Harness」时提示「请将手机和运行 Harness 的电脑连接到同一个局域网」，然后由 App 和后台自动查找、连接和重连。已授权且只有一个可用后台时，直接打开工程聊天；找不到时提示检查后台是否运行，不要求用户填地址或密码。首次绑定仍需确认身份；发现多个后台时只让用户选电脑。当前手填入口仅用于只读诊断，不作为正式流程。
- **发现放在电脑后台侧。** 已验证的 OpenCode V2 服务默认只监听回环；官方 `pair` 负责授权，不等于局域网发现。先验证当前版本是否提供可复用的局域网发现；若没有，则由跟随 Harness 启动的后台组件提供局域网发布及受认证的连接入口，不依赖 PC 版 TalkApp。发现结果只用来定位候选服务，不视为授权；不扫描整个网段，不发送服务密码给未知设备。
- **连接状态由双方管理。** 验证过的后台重新出现时，App 自动恢复同一会话并补读状态；短暂断线不新建会话、不自动重发。后台未启动、Wi-Fi 禁止设备互访、以及凭据失效要分别提示，不能把「同一个 Wi-Fi」显示为「已经连接」。

- 首版只做同 Wi-Fi。使用设备可达的 HTTPS 地址，OpenCode 继续绑定回环；若当前服务不能直接提供符合要求的 HTTPS，就让本机 TLS 入口转发到它。只接受系统信任的证书，或配对时显式验证的证书身份；不关闭证书校验，不启用 OpenTunnel 或公网端口映射。
- 优先复用 OpenCode 的一次性配对链接。先验证在选定 LAN HTTPS 入口上，链接可兑换且原生 API 和事件流都接受所得会话凭据。客户端按实际接口契约保存凭据，放在 Android Keystore 保护的应用私有存储，不写入聊天、日志、导出文件。到期重新配对；取消绑定立即清除本地凭据。不能验证配对凭据时，暂停该路径，不退回明文 HTTP。
- 初次验证只访问 `/api/info` 和只读会话接口，不调用模型。用户在电脑上预先选择允许使用的工程目录；手机首版不接受任意本机路径作为会话位置。若服务器凭据实际可访问其他目录，客户端的目录限制不是安全隔离；要隔离时用专用实例和操作系统权限限制。

## 会话与断线恢复

- 每个设备关联下，按「TalkApp 工程会话/分支 + 工程目录」保存 OpenCode `sessionID`。工程入口中的后续消息复用该 ID，普通聊天不受影响。手机暂不自动把既有聊天整段迁入 OpenCode。
- 发送前持久化本地消息 ID、会话 ID 和提交状态。断线时先刷新该会话的历史、运行状态和待授权列表，再接入事件流；订阅建立后补一次状态以覆盖连接间隙。事件流不负责回放，结果按服务端消息 ID 去重。提交回执丢失时标记「送达待确认」，不自动重发；新任务不能被之前的完成事件误结算。
- 权限提示只对应当前配对设备、`sessionID` 和实际请求 ID；回复「好 / 拒绝」只对被引用的单条待授权生效。刷新后请求已过期或处理过就不再提交。不自动批准、不保存永久授权。继续使用 OpenCode 的实际工具权限策略，不用手机客户端替代它。

## 首版验收顺序

1. 关闭 ADB 和桌面 TalkApp，手机在同 Wi-Fi 通过受认证的 HTTPS 入口验证 `/api/info`，并能看到一条指定的测试会话；错误证书或失效凭据必须拒绝。
2. 同一工程对话发两条测试消息，确认只创建一个 OpenCode 会话；关 Wi-Fi 再打开，补回事件或最终结果，不重复发送。
3. 用无副作用的测试操作验证一次拒绝、一次单次批准，以及过期请求无法误批。真实模型调用留到用户同意后。
